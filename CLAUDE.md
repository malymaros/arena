# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A 2-player turn-based browser arena game (wizard duel on a 4×3 grid — `BOARD` in `engine/constants.js`) built with Express + Socket.IO. No build step — plain JS served statically. Tests and an ESLint config (bug-catching rules only: `no-undef`, unused vars, duplicate keys — no style rules) run in CI (`.github/workflows/ci.yml`: lint + `npm test` + `npm run golden` on every push/PR to `main`). Code comments are in Slovak.

> **Adding a new character?** Read `docs/ADDING_CHARACTERS.md` first — a step-by-step guide (files to touch, questions to ask up front, and the edge-case matrix: defenses, labyrinth, Last Stand, tournament, clone/summon). It exists because adding Naruto touched far more systems than expected.

## Commands

```
npm start        # node server.js → http://localhost:3000
npm run lint     # ESLint (eslint.config.js) - must be clean (0 errors, 0 warnings)
npm test         # integration tests — boots the server on :3996, drives 2 socket clients (test/game-test.mjs)
npm run golden          # golden-master: 64 seeded matches (48 stone bridge + 16 portal realm), timelines compared to test/golden/*.json (server on :3995)
npm run golden:update   # rewrite the golden files - only for a deliberate behaviour change, explain it in the commit
npm run sim             # headless random-bot matches straight on the engine (tools/simulate.mjs, ~1 ms/match; `node tools/simulate.mjs 30 --portal` = Portal Realm + portal invariants, `--swamp` = Shrek Swamp + Shrek invariants)
node tools/difftest.mjs # engine at HEAD vs working tree on identical bot matches - must be 0 diffs for a pure refactor
node tools/browser-smoke.mjs [--compare] [--portal|--swamp]  # CLIENT smoke test: headless Chrome/Edge spectates seeded bot matches (+ char-select hovers, a tournament) at 8× time; fails on JS errors / 4xx; --compare also runs HEAD and diffs the set of loaded sprite files; --portal / --swamp plays every match in Portal Realm / Shrek Swamp
node tools/perf-probe.mjs [--ref <commit>] [--base tmp/perf/x.json]  # CLIENT performance on an emulated phone (CPU 4×): scripted match incl. Last Stand demon + Last Hope, per-window main-thread %, FPS, slow frames, style/paint ms → tmp/perf/; plan + results in docs/PERF_PLAN.md
node tools/touch-smoke.mjs [--shots dir]  # TOUCH controls test: real touch events in an emulated phone (TOUCH_DEVICE=tablet for iPad) - PICK, tap = select + preview / 2nd tap = queue, pickers on the board, cell picker over the board
node tools/screens.mjs [--only phone]  # screenshots of login / char-select / game on 9 screen sizes (desktop, tablet, phone landscape + portrait) into tmp/screens/ - check after any layout change
```

Environment variables: `PORT` (default 3000), `ADMIN_KEY` (the **admin password**: a player who logs in with it instead of a player password is admin — see "Admin"; if unset, nobody is admin), `PLAYER_KEYS` (comma-separated entry passwords), `FORCE_FIRST_STARTER` (`A`|`B` — pins the otherwise random game-1 starter; used by the tests), `ARENA_SEED` (integer - all game randomness goes through the room's `rand()`, re-seeded at every `startMatch`, so identical inputs give bit-identical timelines; the tests default to `1`). Never call `Math.random` in game logic - use `rand()`.

## Architecture

The logic lives in these files (refactor in progress — stages and decisions in `docs/REFACTOR_PLAN.md`):

- `engine/game.js` — authoritative game state and turn resolution, **without sockets**: `createEngine(io)` returns one room's engine (`game` state, `rand`, every action/hit/tile/labyrinth/THE WORLD rule, snapshot redaction, and the player commands `lockIn`/`chooseCharacter`/`chooseTeam`/`timestopActions`/`draftQueue`, plus `autoLock` for the turn-timer expiry). All outside contact goes through the `io` hooks (`emit`, `emitState`, `emitYouAre`, timer hooks, `names`, `awaitingOpponent`, `schedule`, `seed`) — with none of them it runs headless (`tools/simulate.mjs`: thousands of random matches per second). Two **persons** A/B map to board **slots** `p1`/`p2`.
- **Engine mechanic modules** — `engine/labyrinth.js` (redaction for both sides, Ariadne's thread, reveal/end, maze buff), `engine/timestop.js` (THE WORLD pause/frozen actions/resume, `PAUSE`), `engine/laststand.js` (Last Stand / Last Hope / demon, `dealMul`/`recvDmg`), `engine/tiles.js` (end-of-step tile effects, power/block tiles, pre-rolled spawns/IK). Each is a factory `xxxModule(E)`: `E` is the engine's internal scope (getters/setters for `game`/`rand`/`actionSteps` + the functions left in `game.js`); `createEngine` installs them into `E` and destructures their functions, so moved code calls siblings as `E.fn`. The character `ctx` is a separate, narrower API.
- `engine/constants.js` — all balance/timing constants and pure helpers (shared by the engine).
- **Damage pipeline** (`engine/game.js`, section "Damage pipeline"): every action-damage hit goes through **`resolveStrike(defSlot, figs, tl, opts)`** — intercept (THE WORLD) → shared defense (shield / Countess-Onryō mirror immunity / mirror) → soak (stacked clone eats `CLONE_DMG`) → apply (HP, clone poof, one `hit` frame with `parts`) → events (Escanor pride, labyrinth end). Actions enter it by hit shape: `strikeCell(defSlot, who, raw)` (one cell; `who` = `G.figureAt` → `player`/`clone`/`stacked`), `strikeZone(defSlot, playerIn, cloneIn, raw)` (special zones, demon), `strikeOwnerMulti` (a stacked attacker hitting the player twice at once). Never write a new `apply*` variant — extend the pipeline. Status specials (petrify/labyrinth) stay in `applyPetrify`/`applyLabyrinth`/`applyStatusOnClone`.
- `engine/characters/` — **character registry**: one file per character (`index.js` lists them). Each declares its `kit` (`attack`: ortho/diag, `mirrorSlot`: mirror/special1, `meleeDmg`, `healTile` — queue validation reads it), its `special` (`resolve` / `validate`) and, with `mirrorSlot: "special1"`, its `special1` (`args` dir|cell, `resolve` incl. its own mana gate, `validate` — Jotaro, Luffy). Characters talk to the engine only through the explicit **`ctx`** built in `createEngine` (game state, `pushStateFrame`, `strikeZone`/`strikeCell`, statuses, labyrinth, power tile). `doSpecial` is just the mana gate + registry dispatch. A character may also **override actions** (`dash`/`melee` → the Vampire/Onryō charge and own-cell strike, `kit.mirrorImmune`) and react through **hooks** `on: { deploy, hitTaken, roundStart, afterActions, roundEnd, roundEndFx }` (Escanor pride, Werewolf moon, Wanderer mana regen) — see `engine/characters/index.js`. The engine resets per-character state on deployment (`deployReset`: choice or swap) and calls the hooks; it has no branches on character names except side-binding (`SIDE_CHARS`), the trap trigger (engine mechanic, strike via `vampMeleeLand` from `vampires.js`) and a few choreography details. THE WORLD mechanics (`doJotaroWorld`/`runTimestopActions`), labyrinth, Last Stand and tiles live in separate engine modules (see below).
- `shared/geometry.js` — pure board geometry used by **both** the engine and the client (`public/client/*`) (special zones, Escanor/Jotaro/Medusa cells, the diagonal bounce shot, charge paths `runPath`, Luffy's ball zone, and the queue/ghost simulation `simulateQueue`/`simulateClone` — the server validates targets with the very same simulation the client draws as the ghost). Board is passed explicitly (`{w,h}`), cells are `[x,y]`.
- `shared/balance.js` — the single source of balance numbers (see "Game balance constants"); imported by the engine (via `engine/constants.js`) and the client.
- `shared/timing.js` — timeline pacing (`ANIM_SLOW`, every server `*_MS` frame delay); re-exported by `engine/constants.js`, imported by the client wherever a value must match the server.
- `server.js` — Express + Socket.IO only: room registry, seating/reconnect, spectators, the turn timer, and per-person masked emits; each room owns one engine and its socket handlers are thin wrappers over the engine commands.
- `public/client.js` — the client **entry point** (~95 lines): builds the `C` scope for `public/chars/fx/*`, appends the DOM layers that must come after the fx-registry figures (Last Stand/Hope overlays, THE WORLD, YOU marker) and renders the initial state. The client trusts the server's state but replays it via timelines. All logic lives in **`public/client/`** ES modules (refactor stage 7, `docs/REFACTOR_PLAN.md`): state — `session.js` (`me`/`isHost`/`isSpectator`/`board`/`state` as ES live bindings, change only via `setIdentity`/`setSpectator`/`setState`), `playback.js` (timeline-playback flags incl. THE WORLD `ts*`), `planning.js` (queued actions, golden/Last Stand/Hope flags, `openPicker`, `resetPlanning`, `buttonUi`), `actors.js` (figure pose/facing/clone/pride-hold state, `resetPoses`), `last-stand-state.js`; core — `dom.js` (static elements, `TILE_W`/`TILE_H`/`GAP`, `cellToPx`), `sprites.js` (`ANIM_DEF`, `charDirFor`, `ensureSpriteMeta`, `drawSprite`, `ACTOR_W/H`), `fx-registry.js` (`CHAR_FX`, `fxAll`; installed by `initCharFx(C)`), `anim.js`, `placement.js` (`computeFacing`, `pairShift`, `positionActors`); features — `timeline.js` (timeline playback + game end), `socket-handlers.js`, `raf.js` (draw loop), `board-fx.js` (floats, projectiles, auras), `grid.js`, `hud.js`, `queue.js`, `controls.js`, `turn-timer.js`, `the-world.js`, `char-select.js`, `phase-ui.js`, `ghost.js`, `zones.js`, `last-stand.js`, `overlays.js`, `defense-fx.js`, `net.js`, `pix.js`, `peek.js` (the "what does this do" window: touch long-press on an action button = its explanation, on a HUD portrait / tournament mage head = the character window = name + the exact char-select special preview; PC: hover on portrait/head; button texts come from `act()` in `public/chars/common.js`, one text for the PC tooltip and the window) and small ones. New client code goes into the matching module (or a new one) with explicit imports — never back into `client.js`; `npm run lint` (`no-undef`, `no-import-assign`) catches missing imports, and a module imported only for its side effects (e.g. `raf.js`) must keep a bare `import "/client/x.js"`.
- `public/chars/` — **client character registry** (refactor stage 6): one file per character with its client data (`meta` name/sprite dirs, `specialAnim`, own `anims`, `spriteAlias`, head position/crop, `pairShift`, `portraitScale`, teleport FX, char-select `abilityPreview`/`previewCast`, `side`/`vamp`), plus behaviour declarations: `buttons` (tooltip/cost/skin of the melee, special, dash, attack, recharge and mirror buttons — static or `(ui) => …`), `specialTarget` (picker type) and `specialZone` (preview zone from `shared/geometry.js`), board drawing (`boardFit`, `victoryAnim`, `sizeLevel`, `projectile`, `actionAnims`, anim flags `fromStart`/`armCrop`) and planning (`planUi`, `attackPicker`, `aimStopsAtFoe`, `buttonBadge`, `specialReach`, `mirrorSlot`, `planSpecialWarn`); `index.js` documents the fields and composes the tables the client modules import (`CHAR_META`, `SPECIAL_ANIMS`, `HEAD_CROP`, `CHAR_BUTTONS`, …). These files are plain data (importable in Node).
- `public/chars/fx/` — **client choreography registry** (refactor stage 6c): one factory per character `(C) => hooks`, where `C` is the client scope built in `public/client.js` (lazy getters: state, board geometry, DOM layers, `setAnim`/`drawSprite`/… helpers). Hooks (all optional, documented in `fx/index.js`): timeline `effect`, board pose `boardAnim`, centre overlay `centerCast`/`centerCanvas`/`drawCenter`/`spawnCenter`/`ownCenter`/`centerScale`/`centerPlace`, `projectileScale`, round start `roundIntro` (Escanor transform delay), own HUD widgets `hud`, char-select `preview`/`previewZone`/`drawCard`, extra board figures `init`/`position`/`drawBoard`/`stateChar`/`resetActors`/`moved`/`bodyShift` (Jotaro's stand), `levelFloat`, `clearOverlays`. Soldier, Werewolf, Countess, Onryō, Luffy, Jotaro and Escanor live here; the client modules have no per-character name branches left except the shared Soldier-sprite explosion (`spawnExplosionAt`) and the THE WORLD menace (an engine mechanic). New character choreography goes into its own `fx/<key>.js` — never a new `if (char === …)` in `public/client/*`.

### Portal Realm (second arena)

**Read `docs/PORTAL_PLAN.md` first** (approved design 2.1–2.14, test matrix). The lobby has an ARENA choice: **STONE BRIDGE** (internal key `bridge` - the original game, unchanged) or **PORTAL REALM** (`config.arena = "portal"` + `config.portalWeights`; both keys exist ONLY for portal realm so bridge goldens stay bit-identical; `game.arena` = `"portal-realm"` picks the background). Two separate lobby forms with a shared base (`public/client/lobby.js` keeps per-arena state); portal realm has only Damage (2 dmg, 2-flame icon — applied as **two 1-dmg parts** in one blink: one `hit` with `parts:[1,1]`, client float „-1 -1 HP", and Last Stand/Last Hope ½ is floored per part → ⌊1/2⌋+⌊1/2⌋ = 0, same as on the bridge, so Last Hope at 1 HP survives; Naruto's cosmetic `clone_hit` carries the same parts) + Insta-kill tiles (default 90/10) and portal type weights (classic/hp/mana/power/nodef = Def-breaker, default 70/5/5/10/10); phone: arena buttons replace the ARENA title, the weights column has TILES | PORTALS tabs. **Portals** live on the outer edges of edge cells (`game.portals = [{ id: "A"–"G", type, ends: [{x,y,side},…] }]`, public, also to a cursed labyrinth player); `config.portalsPerRound` pairs (lobby "Per round" next to Classic, 1–7, default 2) at game start + the same number as the very last thing of every round (`spawnPortalRound` → `spawnPortalPair`, any free edge incl. both edges of one corner, max 7 pairs - a full board spawns nothing until some close). Geometry is shared in `shared/geometry.js` (`portalStep`, `runPathPortals`, `shotPathPortals`, `escanorAnchor`, portal-aware `luffyBallLanding`/`simulateQueue`/`simulateClone`) - without portals every function returns exactly the old result. Engine: `engine/portals.js` (spawn, `walkAction` = move/dash with owner+clone in lockstep, `closePortals`, `bodyEffect` HP/mana, THE WORLD defers close+effect to resume, `threadCut`); straight shots in `doBasic` (range 3 total, 3/2/1 continues, a shot that went through a portal hits the shooter/own clone too - `selfStrike`), charges (werewolf orthogonal, vampire/onryō), Escanor's sun (only when F is off-board) and Luffy's ball go through portals; diagonal shots/charges never enter. A pair closes right after one traversal (simultaneous traversals in the same beat all pass). **Pacing** (`shared/timing.js`): a shot step through a portal lasts `PORTAL_SHOT_STEP_MS` (the exit end pulses first - `portalBeacon`); a move/dash/charge through portals lasts `portalWalkMs(cells, passes)` - never faster than the fastest bridge run (3 cells per `MOVE_DELAY_MS`), a long run simply takes longer (`walkDelay` in `engine/portals.js`). Types: hp/mana act on the **body**, power (+2 flat) / nodef (`defBreak` → `dispel` frame, defense consumed, hit lands) on the **attack**; Def-breaker applies ONLY to basic-attack shots, power also to Escanor's sun and Luffy's ball (+ its body effects), charges (werewolf/vampire/onryō) get ONLY the body effects (balance change 2026-10-29). A mirror reflecting an attack that came through a (now closed) portal hits the wall (`reflectVoid` → `reflect_void`, nobody takes dmg); charges/ball reflect directly. New effects: `portal_walk`, `portal_close`, `portal_spawn`, charge `portal`/`aura`, `dispel`, mirror `void`, `reflect_void`, hit `portalBonus`/`self`, `thread_cut` (hunter never sees it). Client: `public/client/portals.js` (pixel rift portals + runes, open/close by snapshot diff, figure/projectile passage via WAAPI translate/scale), `portal-art.js` (approved visuals, rift frames rendered once with baked glow), `arena-bg.js` (portal realm painted background in full resolution + "living background" `#arena-fx`, lite variant under `.perf-lite`). Visual mock-up of the approved design: `public/dev/portal-realm.html`. Tests: `test/portals.mjs`.

### Shrek Swamp (third arena)

**Read `docs/SWAMP_PLAN.md` first** (rules, edge-case decisions, tests). Lobby card **SHREK SWAMP** (`config.arena = "swamp"` → `game.arena = "shrek-swamp"`; the key exists only in the swamp, bridge/portal goldens stay bit-identical). **No special tiles** (weights zeroed server-side) - instead **Shrek**, a neutral NPC (owner's decision 2026-10-30: never a playable character). ### Match lifecycle, lobby & series

`game.phase` is a state machine: `lobby → (team_select) → playing → match_over` (`team_select` only in the tournament format). The **first connected person (A) is the host** and sees the lobby setup screen; person B sees a waiting screen. The host emits `configure_match` (`{ format, tilesPerRound, tileWeights, timer, tilePreview, colorPref, randomChars }`, validated/sanitized server-side; tile percentages must sum to exactly 100) which starts the match. Format is `single | bo3 | tournament` (`MATCH_FORMATS` = wins needed: 1/2/3). Identity is the **person** (A/B); the **slot** `p1`/`p2` is the left/right board role. At `configure_match`, `startMatch()` **randomly assigns persons to slots** (`game.seats`; `FORCE_FIRST_STARTER=A|B` env pins who gets `p1` — the tests rely on this) and the seats are then **fixed for the whole series**. `p1` = **white**, left, and **always starts game 1**; in a series (bo3/tournament) the game starter **alternates per game** (odd games open with `p1`/white, even with `p2`/black); within a game the per-round starter flips each round (turn resets to 1 each game). After the roll the server broadcasts `color_roll`; the client then plays a **spinning-arrow yin-yang animation** (`#color-roll` overlay above char-select) whose pointer lands on the player's own colour — the assignment already happened server-side, the wheel is pure theatre. **Random characters** (`config.randomChars`, lobby toggle, default off; the key is present in `config` only when on, so the goldens are unaffected): single/bo3 — `startGame()` assigns both characters with `rand()` before **every** game (pool = `CHARS` + the side-chars bound to that slot; mirror picks allowed; manual `choose_character` is then a no-op) and delays the planning timer by `charRollMs()` (+ `COLOR_ROLL_MS` in game 1 when the colour is rolled); tournament — `startMatch()` rolls each team (3 distinct, roll order = roster order) instead of the draft, then the normal roster char-select picks the starter. Either way it emits `char_roll` **before** the state; the client (`public/client/char-roll.js`, `#char-roll` overlay just under `#color-roll`) shows only the player's own 3×4 head grid (own palette, hidden side-chars glitch, a muted `???` future slot the cursor never enters), hops the cursor(s) with deceleration (timing in `shared/timing.js` `ROLL_*`), holds a beat on the target, then reveals (name + `ui.pick` + the intro voice `ui.hover_char.<char>`; hop = `ui.random_hop`). Pure theatre like the colour wheel: spectators see nothing, a reload mid-roll shows the result directly, the turn timer display is suppressed while it runs. The right side (`p2`, black) always renders its mages with the alternative "albino" palette (`alt-color`), consistently across board, HUD portrait, ghost, projectiles, tournament mage heads and char-select; `p2`'s char-select is additionally **mirrored** (`#char-select.p2-side` flips card sprites and the mini-caster, `renderAbilityPreview` mirrors the caster position and the directional special's direction). Series score is tracked **per person** in `game.seriesWins` and exposed per current slot via `seriesSnapshot()`. Characters are **re-picked before every game** (each game clears `char` → char-select reappears). When a game ends, `handleGameEnd()` records the win and emits `game_result` (`{ gameWinner, series, matchOver }`); on `matchOver` it also emits `game_over` (series decided), otherwise it schedules the next game (`new_game` + fresh `playing` state) after the client has played out the timeline. The **turn timer** (`config.timer` = `off | 10 | 30 | 60 | quickdraw`) is **client-driven**: the client counts down and on expiry auto-locks — actions the player already queued stay, **every unfilled slot becomes a `pass`** (golden actions are never auto-added); the server backstop (`autoLock` → `fillFromDraft`) does the same from the player's draft. **`pass`** = the player is "thinking": a `pass` effect (client: 💭 THINKING float + −N MANA float, 💭 badge in the round log), costs `PASS_MANA_COST` (2) mana **per pass** (never below 0) and is a normal action — it **consumes the opponent's armed shield/mirror**. It can repeat in a queue (like `stoned`); there are no random auto-filled actions anymore.

### Tournament (team draft + HP/mana carry-over)

First-to-3 series where each person drafts a **team of `TEAM_SIZE` (3) characters** from the full `CHARS` pool. After `configure_match` the phase goes to `team_select`: each player emits `choose_team` (3 unique characters, once per match). The draft is **blind** — `snapshotFor` masks the opponent's `roster` until both confirmed; `rosterReady` stays public so the client can show "opponent is ready". When both confirm, `finishTeamSelect()` builds `game.mageHp`/`game.mageMana` (keyed per person by their roster) and starts game 1. Every mage's HP and mana **carry over between games** (saved at game end and at swap); a defeated mage drops to 0 HP = permanently dead — cannot be picked or swapped in (skull head in the HUD, dead card in char-select). Characters are re-picked before each game **from the player's own roster only** (client `roster-mode` merges both char-select pages via `display: contents` and hides off-roster cards). During a round a player may queue up to **2 `swap` actions** (`{type:"swap", to}` — free, two-phase teleport animation, position stays; target must be an own-roster living mage, not the mage the round started with, each target at most once) — validated in `validQueue()`, executed in `doSwap()`; the rest of the round is played by the new mage. The HUD shows each side's roster as **3 animated mage heads** (`renderMageHeads`, order = draft order from `state.roster`); own living non-current heads toggle a swap on click. `rosterHp`/`rosterMana` (stored per-mage values per slot) are public. **Tournament × labyrinth:** while any labyrinth is active, swap is **forbidden for both sides** (rejected at `lock_in`; a swap already queued when the curse lands mid-round resolves as `invalid`) and the mage heads are hidden on both sides (`.lab-hidden`, reappearing at `labyrinth_end`); the opponent's `rosterMana` is redacted **both ways** (like live mana); a **lethal tile/IK hit** during a labyrinth plays the same reveal sequence as an action hit (`revealLabyrinths` before the tile frames, `endLabyrinths` after the hit) so a game never ends inside the fog. **Tournament × Last Stand:** the buffed player cannot swap in the final round (rejected in `validQueue`, guarded in `doSwap`, heads not clickable) — otherwise the demon's full heal would be banked into the roster at swap time and the doom would kill the substitute instead of the mage who made the pact.

### Server-authoritative timeline model

The core pattern: the client does **not** simulate the game state. Each turn, both players queue exactly 3 actions (`move`, `dash`, `recharge`, `attack`, `melee`, `special`, `shield`, `mirror`, `shield_breaker`, `mirror_breaker`) — each action type at most once per round (a defense and its breaker share one slot), enforced both in the client UI and in server-side `validQueue()` — and emit `lock_in`. Two optional extra actions can wrap the queue: the round's **non-starter** may prepend a **golden pre-action** — either `golden_shield` (3 mana, behaves exactly like a shield) or `golden_mirror` (5 mana, behaves exactly like a mirror), the two are mutually exclusive and both resolve before the starter's first action — and **either player** may append `golden_mana` (resolved after everything else in the round; +6 mana for HP, the HP cost grows by 1 with each use per game — tracked in `manaRefills`, refused if it would kill or mana is full). `move`, `dash` and `attack` carry a `dir` (up/down/left/right): the basic attack fires in the chosen direction and hits the first opponent in its path (damage falloff 3/2/1 by distance, never its own cell), so aiming is a prediction of where the opponent will be when the action resolves. `dash` (4 mana) moves up to 2 cells in one direction (clamped at the board edge). `melee` (4 mana, 8 dmg) hits only an opponent sharing the caster's cell. **Action into a wall:** a directional action that "has nowhere to go" (move/dash into the board edge, or an attack fired off the board from an edge cell) is **not crossed out and is not free** — if you have the mana it is spent and the action *executes* in place (dash/move → `wall_bump` OUT-OF-BOUNDS twitch; attack → an `attack_swing` whiff frame, the shot fizzling at the edge). This closes the old exploit where a player filled slots with impossible-into-wall actions to passively hoard mana. Only a genuine **lack of mana** still yields an `invalid` (crossed-out, refunded); `move` is free so it always just executes. For planning previews the client simulates its **own** queued moves ("ghost"): a translucent sprite shows the post-move position and aim/special previews are computed from the position valid at that point in the queue (`simulatedPositions()`/`ghostPos()` in `public/client/ghost.js`). When both are locked, `resolveTurn()` executes actions interleaved (the round starter flips each round; game 1 is always opened by `p1`/white, in a series the game starter alternates per game), and builds a **timeline** — an array of state snapshots, each with an `effects` array (`charge`, `hit`, `recharge`, `special`, `invalid`) and a `delayMs`. The whole timeline is emitted in one `state` event; the client plays it back frame-by-frame with `setTimeout` in `schedulePlayTimeline()`, mapping effects to sprite animations.

When changing game logic, the server-side `do*` action functions must push frames via `pushStateFrame()` for anything the client should animate — state changes without frames render as teleports.

Turn resolution checks for a winner (`hp <= 0`) after **every individual action and every individual tile hit** and aborts the rest of the turn on lethal — the first death ends the game, so a draw cannot occur. At game end `game_result` is emitted alongside the final timeline (and `game_over` too if the series is decided); the client deliberately delays the overlay until attack/death animations finish (`serverWinner`/`serverGameResult` + `showGameOverSequence`, or `playGameEndAnim` → `showIntermission` between games in a series).

### Socket protocol

Client → server: `configure_match` (host only, in `lobby` phase), `choose_team` (tournament only — 3 unique characters, in `team_select` phase, once per match), `choose_character` (fire | lightning | wanderer | medusa | minotaur | naruto | escanor | soldier | werewolf, plus the side-bound countess + luffy (p1 only) / onre + jotaro (p2 only) outside tournament — only in `playing` phase, once per game; in tournament only from the own roster), `lock_in` (array of 3 actions — incl. `shield_breaker`/`mirror_breaker`, each sharing its defense's slot — or 4 with `golden_shield`/`golden_mirror` first — only valid from the round's non-starter; only in `playing` phase; in tournament the queue may contain up to 2 `swap` actions; the soldier's `special` carries a target `cell:{x,y}`, the werewolf's `special` a `dir` from 8 directions; countess/onre: `attack` carries a **diagonal** `dir`, `dash` is their **charge** (same 4 orthogonal dirs), `melee` has no dir (own cell only), `special` a trap `cell:{x,y}`; jotaro: `attack` carries a **diagonal** `dir`, `special1` (mirror slot) a `dir` left/right, `special` = THE WORLD (no args) or Special 2 (`dir` left/right) after it; luffy: diagonal `attack`, `special1` (mirror slot) a target `cell:{x,y}` (not his own ghost cell), `special` = the ball or Special 2, both `dir` left/right), `timestop_actions` (jotaro only, during a THE WORLD pause — 3 frozen actions), `retry`, `admin_reset_all`.
Server → client: `you_are` (`{ slot, isHost }`; slot is rolled at match start and fixed for the series), `color_roll` (after `configure_match` — trigger for the client-side colour-wheel animation; the seat assignment is already done), `char_roll` (`{ team, picks: { p1: [...], p2: [...] }, afterColor }` — random characters: what the server just assigned, the client animates its own slot's picks), `state` (snapshot incl. `phase`/`config`/`series`, tournament also `roster`/`rosterReady`/`mageDead`/`rosterHp`/`rosterMana` + own `mageHp`/`mageMana`, optionally with `timeline`; while a THE WORLD pause is open it also carries `timestop: { slot }`), `game_result` (per-game outcome), `new_game` (next game in series — reset round UI, keep score), `game_over` (series decided), `reset`, `spectators` (`{ count, seatFree }` — see "Spectators"). Room lifecycle (outside the game): `create_room` / `join_room` / `spectate_room` / `take_seat` (spectator → free seat) / `leave_room` ↔ `rooms` / `spectator` (`{ roomId }`) / `join_denied`.

### Game balance constants

**All balance numbers live in `shared/balance.js`** — HP/mana, every action cost, character damage (`SPECIAL_ZONE_DMG`, `WOLF_MOON_DMG`, `VAMP_*`, `JOTARO_*`, `LUFFY_*`…), tile values and the Last Stand / Last Hope / maze multipliers. The engine reads them through the re-export in `engine/constants.js` (same names); the client imports the same module and **builds every tooltip, cost badge and preview number from it** (`public/chars/<key>.js` via template literals, generic buttons via `public/client/balance-ui.js`, which also fills the static buttons in `index.html` — the HTML carries no numbers; the planning mana check in `ghost.js` uses it too). **Changing balance = editing only `shared/balance.js`** (then `npm run golden:update` with an explanation). `test/balance-ui.mjs` (part of `npm test`) fails if a cost/dmg number is hardcoded in client UI text again and checks the character tooltips show the balance values. Never write a balance number into a UI string — interpolate it. Animation pacing (`*_MS` timeline delays, `ANIM_SLOW`) lives in **`shared/timing.js`** — re-exported by `engine/constants.js` and imported directly by the client, so a value both sides need exists exactly once (never re-declare it on the client). Client-only animation lengths in `public/client/anim.js` (`ATTACK_SWING_MS`, etc.; `MOVE_MS` lives in `shared/timing.js`) must still cover the server's `delayMs` values or animations desync from the timeline playback.

Character specials differ by hit zone: fire hits the whole row (5 dmg) — and Fire is **no longer immune to Damage tiles** (takes the normal 1 dmg); instead, while he *stands on a Damage tile* when the special resolves, its range widens to his row **±1** (`fireOnDmgTile()` in `engine/game.js`, mirrored in the client `cellsForSpecialPreview` fire branch reading `state.tiles`; from the middle row that is the whole 3-tall board, from an edge row 2 rows) and that Damage tile is then **consumed** — after the cast beats `doSpecial` filters it out of `game.tiles` and emits a `tile_consume` effect (client `spawnTileConsumeFx` short flare); the tile is spent **whether or not the special hit/was blocked**, so the boost is a one-shot rather than a campable buff (and removing it mid-round also stops the per-step tile ticks for the rest of that round) — lightning hits every cell of the **opposite chess-color** to the one it stands on — half the board, and each orthogonal move flips its parity (3 dmg) — wanderer hits diagonal-adjacent only (8 dmg). Medusa's special is directional (left/right), deals no damage and **petrifies** (target skips its next 2 basic actions; golden actions are skipped without consuming the counter). Minotaur's special covers the **whole board**, deals no damage and banishes the opponent into the **labyrinth** (see below). Naruto's special is **self-range** and summons a **shadow clone** (see below). Escanor's special is **directional (left/right)** and deals **8 dmg** to a zone whose size grows with his **Pride level** (see below). The Soldier's special is a **player-picked target cell** — a sniper beam dealing **10 dmg** to whoever stands on that cell when it fires (see below). The Werewolf's special is an **8-directional charge** (diagonals included) that moves the caster and deals **2/4/6/8 dmg by his Moon phase** (see below). Vampire's and Onryō's special is a **player-picked hidden trap cell** (see below). The hit logic is in `specialDamageAndHit()` / the medusa+minotaur+naruto+escanor+soldier+werewolf+countess/onre branches of `doSpecial()` (server) and the client `cellsForSpecialPreview()` (hover/cast preview) — both read the zone geometry from **`shared/geometry.js`** (one ES module imported by the engine and by the client, served at `/shared/`; never re-implement a zone/path on one side) (the soldier's and the trap duo's "zone" travels in the action's `cell`, so their branches and the client picker/hover handle it instead of `specialZoneHas`; the werewolf's path depends on the opponent's live position — the client preview receives it via `meState.foe`).

**Pride (Escanor):** Escanor carries a per-mage **`pride` level 0–3** (`newPlayer`/`cloneActor`, public in snapshots). His directional special (`escanorCells(actor, dir)` ↔ client `cellsForSpecialPreview`) hits a zone anchored at the cell one step in the chosen direction `F`: **0** = just `F`; **1** = `F` + its 4 diagonals; **2** = the 3×3 around `F` (incl. Escanor's own cell); **3** = the whole board. **Throw off the board:** if `F` is out of bounds (cast toward the adjacent edge) the zone is empty **even at pride 3** — the whole throw goes out: the action still *executes* per the wall rule (mana spent, not crossed out), the choreography plays with the sun flying off the board and fading (no burst) and an OUT OF BOUNDS float; the zone previews (hover/ghost) highlight nothing, same as aiming a basic attack off the board. Always 8 dmg, 5 mana, goes through defenses like any dmg special (shield blocks, mirror reflects 8 back). Pride evolves at **end of each round** in `resolveTurn`: if he queued **shield/mirror/golden shield/golden mirror** that round **or took a hit from the opponent** → **−1**, else **+1** (always a single ±1 step, the conditions don't stack; clamp 0–3); reset to 0 on character choice and on tournament swap-in. "Took a hit" = any HP loss caused by the opponent's action — incl. a mirror reflect of Escanor's own attack — tracked by `notePrideHit()` in the damage pipeline `resolveStrike` (undefended HP loss and the mirror-reflect branch) into the per-round `player.prideHit` flag; tile/IK damage and the no-damage statuses (petrify, banish) do **not** count. **HUD range minimap:** 4 static mini-boards (pride 0–3, the same abstract board as the char-select preview — Escanor at `abilityPreview.caster`, facing right; p2 mirrored), only the current pride's one is visible; it does not follow his position. **Pride is shown as the character's on-board size** — the board sprite scales `1.2^pride` from the feet (`escPrideMul`, `transform-origin` at `ESC_FEET_FRAC`; the YOU-flag, ghost and pair-shift math account for it) — a public tell the opponent reads. **Transform intro:** in-game Escanor starts as `WeakIdle` (weak "day" form); at the **first round's playback** (once per deployment — game start or swap-in, tracked by `escTransformed`) a one-shot `Transform` animation plays before any action (parallel if both are Escanor), after which the idle is `Idle` (Stand, strong form). **Special choreography:** the big centre cast sprite is `WinSun` (Escanor hoisting a growing sun) while the small board figure plays `WinSunBoard` — the raise plays **once**, then only the mouth moves and the sun flickers (the sheet's last 4 frames, looped via `ANIM_DEF` `loopFrom`, which needs a draw time relative to the anim start — `animState.start`); after the cast the small figure switches to `CruelSunHold`, during the sun's flight to the target it plays `WinTalk` (mouth only — no sun, no re-raise) and a `SunBurst`→`SunFade` FX (`spawnSunFxAt`) plays on the target cell. Assets live in `public/assets/escanor/` (+ `escanor_2/` = green clothing recoloured red for p2); the reproducible extraction pipeline is `tools/sprites-escanor/`.

**Shadow clone (Naruto):** the special (5 mana, cannot be blocked/mirrored) requires Naruto to stand on his cell **without the opponent** — the opponent standing on Naruto's cell is the **only way to block the summon**, so it still **costs the mana** (any existing clone is killed first — as in a recast — then seals play + a `not_alone` whiff, but no new clone spawns); a recast first kills the active clone (as if hit), then summons a fresh one on Naruto's cell. State lives in `player.clone = {x,y} | null` (serialized in snapshots; `redactActor` strips it for a cursed viewer). The clone **copies every basic action in parallel** with its owner — same frames/beats — with one inversion: **the vertical axis is mirrored for both movement and the basic attack** (owner moves up → clone moves down; owner shoots up → clone shoots down; horizontal is identical; dash keeps its own board clamp via `moveCloneSteps`). A vertical move/dash/attack at the board edge makes whichever figure is blocked play a **`wall_bump`** (OUT OF BOUNDS twitch) while the other still moves and mana is still spent; when *neither* figure can move the action still **executes** (both play `wall_bump`, mana still spent — it is never crossed out, see the "action into a wall" rule below). Because both figures split symmetrically on a vertical action, the opponent's **action log / round-script anonymizes Naruto's vertical direction to `↕`** (`displayDir` — up/down would reveal which figure is real; horizontal stays). Copied attacks/melee deal the **same damage as Naruto himself** — the basic shot uses full distance falloff (`Math.max(1, BASIC_DMG_MAX - dist)`) measured from the clone's own cell, melee deals the full `MELEE_DMG`, both scaled by the owner's Last Stand/Last Hope (`dealMul` ×2 / ×4) and maze (`labyrinthMul` ×2) multipliers. Because a clone **stacked on the owner's cell** fires/melees the same target in parallel, the pair lands two full hits = **double damage** (this stacks only for horizontal shots and melee; a vertical shot still splits up/down via the inversion). On an **undefended** target the two simultaneous hits merge into **one strike** (`strikeOwnerMulti` → single `hit` frame with `dmg` total + `parts`; the client prints one „-n -n HP" float and HP drops at once), and the two identical horizontal projectiles render as a **single projectile** (the client dedupes the clone's charge that exactly overlaps the owner's). `CLONE_DMG = 1` now denotes only the clone's **soak** — the flat amount it eats when a shot passes through the stacked pair before the rest carries on to Naruto (its offense and its mirror reflect are both full, Naruto-equal); recharge is visual-only on the clone (mana is the owner's single pool — the `recharge` effect carries both cells so the client shows the aura on both); defenses are the **owner's shared `shield`/`mirror` flags** (armed and consumed together, identical glow on both sprites — the pair is visually indistinguishable; the client duplicates defense/mana floats via `cloneFloat`). The clone has no HP: **any connecting hit removes it** (`killClone` → `clone_die` frame) — enemy projectiles (a clone standing **apart** from the owner is a decoy that eats a shot whole and lets it fly on as smoke; a clone **stacked on the owner's cell** soaks only `CLONE_DMG` and the **rest of the shot passes through to the owner** — it is not a full shield, and in a labyrinth that surplus hit on the real owner reveals & ends the maze like any other), melee (**same stacked rule as a shot**: a decoy clone eats the strike whole; a **stacked** clone soaks only `CLONE_DMG` and the rest of the melee lands on the owner — undefended and defended alike via `strikeCell(…, "stacked", …)`, and the stacked hit reveals & ends a labyrinth like a real hit), zone specials (they strike player **and** clone in the same action; a shared defense reacts on **both figures at once, each from its own cell, in a single synchronized beat** (a clone **stacked** on the owner reacts together with him as **one figure** - one block / one beam, the same pair rule as for a shot) — the zone special and the demon route through `strikeZone(defSlot, playerIn, cloneIn, raw, tl)`, which emits both blocks / both mirror-beams / both hits in the *same* frame so nothing plays sequentially: a **shield** breaks on the player *and* the clone (no damage either way), and a **mirror** reflects from both — both bounce the **full incoming dmg** (the clone reflects the same damage it took, exactly like the player's mirror — not a flat `CLONE_DMG`), so a mirrored wanderer special that hit both deals the attacker `8 + 8` **as one combined `hit` frame with `parts`** — a single „-8 -8 HP" float, HP deducted at once; undefended, a clone **stacked on the owner's cell** soaks `CLONE_DMG` off the zone/demon dmg (the owner takes the rest — same rule as a shot through the pair) while a decoy clone hit on its **own** cell dampens nothing (the owner takes the full dmg) — either way the clone poofs and the owner's hit land in the same beat. A **defended stacked pair** hit by a shot goes through `strikeCell(…, "stacked", …)` (the `pair` mode of `resolveStrike`) — the shared defense reacts as one figure in one beat: a single block frame, or a single mirror beam + one combined `parts` hit on the attacker (`fromClone`: every reflection returns to the shooter — the attacker's clone dissolves, no HP lands). A clone-only hit (on an **undefended** stacked pair the clone poof and the through-hit play in **one beat**, like a zone) reflects the **full incoming dmg** back at the attacker), Medusa's petrify (destroys the clone unless defended), the demon attack, and **IK tiles**. Minotaur's banish does **not** kill the clone — the labyrinth curse affects only the real owner, who keeps his clone in the maze; for both statuses a clone-side **mirror** still reflects the status onto the caster on clone-only contact. A dmg tile shows a cosmetic `clone_hit` −1 float but does not kill it (**deliberate design decision** — the "any damage dissolves the clone" rule covers hits by *actions* only; a dmg tile killing it would make the clone too weak — do not "fix"); the clone never consumes heal/mana pickups (an untaken pickup betrays which figure is the clone). **The clone attacks and takes reflections like a normal player; any damage dissolves it**: an opponent's mirror reflecting a **clone-originated** hit — whether it struck the real opponent, his decoy clone or his stacked pair — sends every reflection back to the shooter, so the attacker's clone dissolves and the owner takes nothing (`resolveStrike` option `fromClone`; the beam aims at the clone's cell, never revealing the real Naruto). The clone dies with the owner's death, swap (`doSwap`) and at game end (`resolveTurn` `ended` cleanup). **Clone × labyrinth:** a hit on a **decoy** clone (standing apart from the owner) never reveals nor ends a labyrinth and the cursed shooter must not learn about it — the killing projectile flies on to the board edge (smoke pass-through); a hit on a **stacked** clone is different, since the surplus damage lands on the real owner and that hit reveals & ends the maze normally and `clone_die`/`clone_hit` effects are redacted like other opponent-side effects; a hit **by** the clone is a normal action hit (ends the labyrinth, blocked/mirrored included). The clone counts for Ariadne-thread crossings both ways (`trackCloneSteps` + the clone check in `trackSteps` — the cursed player sees a silhouette at the meeting cell, not knowing it was the clone). Client-side the clone renders via per-slot `cloneEls` canvases (positioned in `positionActors`, drawn in the raf mirroring the owner's `animState` except hurt/dead — a tile hit on the clone triggers an independent `cloneFlinch` hurt-pose + `-N HP` float so it doesn't read as invulnerable; it does **not** mirror Last Stand visuals — `actorFilter(slot, now, true)` skips the golden death-glow. The clone is **always visible** (both sides — you can always see Naruto has a clone): while sharing the owner's cell it stands a few px beside him (`STACK_OFFSET`) and semi-transparent, and when separated it is full-opacity and identical; it **always slides** (never pops/vanishes in place), so splitting and merging read as two independent figures moving in parallel from the shared cell) plus a `cloneGhost` planning preview (`simulatedClonePos`); the summon choreography is `clone_summon` (owner + one copy on the same cell, mirrored to face the owner, both play `Special_2.png` via `spawnCloneSummonFx`) followed by `clone_born`.

**Sniper beam (Soldier):** the special (5 mana, **10 dmg**) carries a **target cell** picked on a mini-map that pops under the special button (`buildCellPicker` in `public/client/controls.js`): the player may pick **any cell except the opponent's current cell** (and the cell of the opponent's shadow clone — both figures are blocked, otherwise the picker would leak which one is real) **and except his own ghost position** at that point of the queue (after his already-queued move/dash — `ghostPos()`; the server re-validates all of this in `validQueue()` with its own queue simulation incl. tournament swaps, and `randomSoldierTarget()` mirrors the rules for the timeout auto-fill). The point: the opponent takes the hit **only if they move onto the picked cell** during the round. The beam goes through defenses like any dmg special (shield blocks, mirror reflects the full 10) and never harms the Soldier himself (his own cell can't be picked; the beam only strikes the opponent/clone). A decoy clone that steps onto the cell dies to the beam via `strikeZone` (clone-only hit, no owner damage). **Soldier × labyrinth:** while the Soldier is cursed the opponent's cell is **not blocked** in the picker/validation (blocking it would reveal the hunter's position — the server redacts `x/y`, so the client couldn't block it anyway) — the cursed Soldier fires blind and **may hit a standing hunter**; a landing hit plays the usual `revealLabyrinths` → hit → `endLabyrinths` sequence. **Choreography:** one powerful sniper shot, not a burst — a single long **aim** frame (`SOLDIER_AIM_MS`, replaces the old 3× cast beats): the centre overlay and board figure **hold Shot_2's frame 0** (aiming pose, facing the target) while a faint red **laser sight** settles on the target cell (`spawnSoldierAim` + pulsing `.soldier-aim-dot`; the laser sway/lock-on is the CSS `soldier-aim` animation whose 2.3s must equal `SOLDIER_AIM_MS − SOLDIER_FIRE_MS`); in the last `SOLDIER_FIRE_MS` the fire frames 1–3 play **once** with a muzzle-flash brightness spike (`.soldier-fire`), then one `soldier_beam` frame (`SOLDIER_BEAM_MS`, must match client `spawnSoldierBeam`) — a thin red beam from the gun to the cell + an `Explosion.png` FX (`spawnExplosionAt`) — and only then the hit/block/mirror lands. **Moon charge (Werewolf):** the werewolf carries a per-mage **`moon` phase 0–3** (new moon → crescent → half → full; `newPlayer`/`cloneActor`, public — the on-board size is a tell). The phase is **derived from HP** (`moonLevelFor`: 10 → 0, 9–7 → 1, 6–4 → 2, 3–1 → 3): recomputed at the **end of each round** (after tiles, golden mana and Last Stand heal — the final timeline frame carries the new value; the client compares first/last frame and shows a **float with the new phase icon** above him — the UI never shows numbers or up/down colours, only the moon — and releases the held size after the float) and **immediately at deployment and tournament swap-in** from the carried HP. Defenses cover **the opponent's next action** after activation and are consumed by it even if it dealt no damage: shield (2 mana) blocks all damage, mirror (4 mana) reflects the full damage back at the attacker (applied raw — reflected damage cannot be shielded or re-reflected), golden shield (3 mana, pre-round extra action of the non-starter) sets the same `shield` flag, and golden mirror (5 mana, the same pre-round slot) sets the same `mirror` flag. Clicking the shield / mirror button opens a picker (`#shield-picker` / `#mirror-def-picker`, locks the other buttons like a direction picker): the defense (BLOCK / REFLECT) **or** its breaker — they share the slot (`DEFENSE_SLOT` in `engine/constants.js` + `controls.js`; a golden shield/mirror also excludes its breaker). Cost = the defense's cost (`SHIELD_COST` / `MIRROR_COST`), dmg `SHIELD_BREAKER_DMG` 2 / `MIRROR_BREAKER_DMG` 4. It targets the opponent's defense armed **right now** (= the breaker is the action it covers), not a cell: **matching** defense → broken (consumed) + the hit lands through `resolveStrike` (`kind: "breaker"`; a Naruto clone dies with it, labyrinth reveal/end, Escanor pride, Last Stand/Hope/maze multipliers); **other** defense → normal pipeline (a shield blocks a Mirror Breaker, a mirror reflects a Shield Breaker onto the attacker — the Vampire/Onryō mirror immunity does **not** apply to breakers); **no** defense → nothing (mana spent). Never consumes/boosts a power tile, the Def-blocker tile doesn't forbid it. **No golden breaker** (a golden pre-action runs before any opponent defense can exist). Jotaro/Luffy have no Mirror Breaker. **THE WORLD:** Jotaro may play `shield_breaker` frozen — it breaks the captured shield immediately and frozen hits are then evaluated **in order** (hits before the breaker were blocked by the shield and are dropped, hits after it land: breaker → melee = both, melee → breaker = breaker only). Timeline effect `breaker` (`from`, `target`, `what`, `result`: break | block | reflect | none, `gold`; delay `BREAKER_BREAK_MS` / `BREAKER_SHORT_MS` in `shared/timing.js`) → client `public/client/breaker-fx.js`: the attacker holds its range-attack pose, a continuous beam in the breaker's colour (shield cyan / mirror purple); on a break the defense barrier heats up (defense colour → orange → red → white), cracks in 3 waves and shatters (+ board shake, „SHIELD BROKEN!" / „MIRROR SHATTERED!"), other defense = the beam goes out and the next frame plays the real block/reflect, no defense = the beam just dissolves. Breaker buttons/badges: dark blood red `#4a0b0e`, icon = the defense emoji in the „noir" tone (`pix.js` `breakerIco` / `data-tone="noir"`: greyscale, the mirror's gold frame ebony). Tests: `test/breaker.mjs`.

Special tiles spawn at the start of every round — **`config.tilesPerRound` (1–3) rolls per round**, each typed by `config.tileWeights` (`dmg`/`heal`/`mana`/`ik`/`power`/`block` percentages summing to 100; `rollTileType()`; defaults 50/10/10/10/10/10). The randomness is **pre-rolled one round ahead** (`rollPendingTiles()` → `game.pending = { ikMoves, spawns }`; constraints are evaluated against the *future* board — announced IK destinations + announced spawns — which stays valid because tiles can only *disappear* mid-round): during a round both players see where tiles will appear and where each IK will move, and at the round transition `endOfRoundTiles()` commits the announced set and rolls a fresh one — both land in the final mini-frame, so the client shows new tiles + the new preview together with the "ROUND N" banner at the start of the next round (game-start roll happens in `startGame()`, so the preview exists already while planning round 1). The **preview is a lobby toggle** (`config.tilePreview`, host-set): when off the server still pre-rolls internally but strips `pending` from snapshots. Client draws pending cells as a small static semi-transparent ghost icon in the cell corner (`.tile-pending` — deliberately subtle, no blink/pulse/cell tint; a full centered icon = a tile that's already live). **Labyrinth:** pending previews follow the same redaction as live tiles (`redactTilesFor` filters `pending.spawns` too — dmg/IK previews always visible to the cursed player, heal/mana previews only when they or their shadow clone stand on that exact cell). Tiles resolve at the **end of each step** in `endOfStepTileEffects()`: dmg tiles are permanent (1 dmg if standing on them), heal/mana are the only consumables (taken by the round starter if both players share the cell; a heal tile gives +1 HP — except **Lightning**, whom it heals to full HP), and IK tiles (10 dmg) are overlays that hide tiles beneath them. **IK is now a list (`game.iks`), multiple allowed** — every IK relocates each round (to its pre-announced `pending.ikMoves` cell) and may overlap other tiles and players; the only constraint is that two IK tiles never share a cell. **Full-board fallback:** when a rolled dmg/heal/mana/power/block spawn finds no legal cell (every cell already holds a tile or an announced one), the roll converts to an **IK spawn regardless of the configured weights** (IK may overlay tiles) — a late-game safety valve so a saturated board keeps escalating instead of silently skipping spawns. Tile damage bypasses all defenses (shield/mirror).

**Power tile** (gold sword icon, consumable): a caster standing on it **at the moment a direct-damage action resolves** gets a flat **+2 dmg** and the tile is **consumed by the use** — even if the action whiffs into a wall, is blocked or mirrored (same anti-camp philosophy as Fire's dmg-tile consumption; `powerBoost()` in `engine/game.js`, called right after the mana deduction). Covered actions: basic attack (incl. the Vampire/Onryō diagonal), melee (incl. Medusa's wide and the Vampire/Onryō own-cell melee), the Vampire/Onryō **charge**, every immediate-dmg special (fire/lightning/wanderer zones, Escanor, Soldier beam, Werewolf charge — for the two charges the **starting cell** counts, the run happens after) and the **demon attack** (10 → 12). NOT covered: status specials (Medusa/Minotaur/Naruto), the Vampire/Onryō **trap** (its dmg lands at trigger time, not at cast). The bonus is **flat, NOT multiplied** by Last Stand/maze multipliers, but a mirror reflects it as part of the full dmg; the hit frame carries `bonus: 2` and the client shows it as a **separate gold „⚡ -2" float** (main float shows the base; the breakdown is omitted when Last Stand ½-receiving would distort it). **Naruto's clone never gets the boost and never consumes the tile** — only the owner's cell/shots count. **Labyrinth:** redacted like heal/mana (torch-cell only), incl. the pending preview.

**Block tile** (grey shield-with-✕ icon, "Def-blocker" in the lobby, permanent): a figure standing on it **cannot cast shield or mirror** (golden variants included) — the action is **crossed out as not-executed with NO mana cost** (`pushInvalid` reason `blocked_shield`/`blocked_mirror`, client float "SHIELD/MIRROR BLOCKED"). This is a deliberate exception to the wall rule (a player on a block tile can idle a slot for free — they pay positionally, and the opponent sees it). The check runs at **execution time**, not in `validQueue` (own position at resolve time isn't plannable — charges stop at foes, traps teleport); the client deliberately shows **no planning warning** on the shield/mirror buttons — the player learns the outcome only from the crossed-out action at playback (owner's decision). **Naruto:** the shared defense arms on both figures at once, so the cast is blocked when the owner **or his clone** stands on a block tile (`defenseBlockedBy()`). An **already-armed** defense keeps working on the tile — the tile only blocks arming. **Escanor pride** and the **wanderer's mirror-regen rule read the queue, not the outcome** — a defense voided by the block tile still costs Escanor −1 pride and still cancels the wanderer's +2 regen. **Labyrinth:** always visible to the cursed player (a hazard, like dmg tiles).

HP and mana both cap at 10 and are rendered in the HUD as 10-segment bars (`renderBar()` in `public/client/hud.js`). Tile size is rectangular, driven by the `--tile-w`/`--tile-h` CSS variables, which `client.js` reads at startup (`TILE_W`/`TILE_H`).

### Sprites and assets

Sprite sheets are horizontal strips in `public/assets/<char>/`; frame count is inferred from `width / height` (frames must be square). Each character's sheets are **preloaded + decoded** as soon as the client knows the character (`preloadChar` in `sprites.js`, called from the `state` handler incl. the tournament roster) and `ensureSpriteMeta` shares an in-flight load - otherwise the first move slid a static pose until `Run.png` arrived. Animation definitions (file, fps, loop) live in `ANIM_DEF` (generic) / the character's `anims` + `specialAnim` in `public/chars/<key>.js`. Characters with a native right-side palette (medusa, minotaur, naruto) have `meta.dirP2` in their `public/chars/<key>.js` (two sprite folders) instead of the CSS `alt-color` filter; medusa/minotaur `Charge.png` projectiles are per-palette recolored copies of fire's fireball, naruto's is a chakra spiral (P2 gold). Minotaur's sheet only has Idle/Walk/Attack/Hurt/Dead — its `spriteAlias` (`public/chars/minotaur.js`) maps the expected `Run.png`/`Attack_1.png`/`Attack_2.png` names onto them. Naruto's assets were extracted from a ripped sheet via the reproducible pipeline in `tools/sprites-naruto/` (see its README); `Special.png` = hand seals (special cast), `Special_2.png` = the clone-summon pose loop. Arena background layers are listed in the client-side `ARENAS_CLIENT` map and loaded from `public/arenas/<key>/`. Background layers render into low-res canvases (`ARENA_RES`, upscaled with `image-rendering: pixelated`); the served layers are **pre-shrunk to `ARENA_RES`** by `node tools/arena-bg/build.mjs` from the full-res originals in `tools/arena-bg/src/` (pixel-identical result, 20 MB → 300 kB) — add new arena art there, never full-res into `public/arenas/`. The lobby's STONE BRIDGE card shows one pre-composed `public/arenas/bridge/thumb.png` (`node tools/arena-bg/thumbs.mjs` — rerun after changing the bridge layers); composing the layers at runtime drew them in download order and sometimes left the card incomplete. `drawSprite` skips a redraw when the canvas already shows the identical frame; any other draw into the canvas or a width/height change invalidates it automatically (`docs/MOBILE.md`, "Výkon").

### Mobile & tablet

**Read `docs/MOBILE.md` before touching layout.** The page is laid out for a fixed minimum of 1720×920 CSS px; on smaller screens `public/client/viewport.js` renders it on a "virtual screen" (`--app-w`/`--app-h`) and shrinks the whole `<body>` with one `transform: scale(--app-scale)` (≥ 1720×920 → scale 1, desktop unchanged). Therefore: never use `window.innerWidth/innerHeight` or `100vw/100vh` — use `appSize()` / `var(--app-w)`/`var(--app-h)`; convert event `clientX/Y` via `appScale()`; append fixed overlays to `body`. Touch-only extras: rotate-to-landscape hint in `public/client/mobile-ui.js`; **touch controls in `public/client/touch.js`** (tap = select + preview via a synthetic `mouseenter`, 2nd tap = execute; pickers moved into `#touch-layer` over the board, fixed at the board centre; char-select PICK button; `:hover` rules stripped) — a new button with a hover preview needs nothing extra, its `mouseenter` handler is reused; PWA manifest `public/manifest.webmanifest`, icons `public/icons/` (`node tools/make-icons.mjs`). **Phone layout** (`html.phone` = touch + short screen side ≤ 500 px, `isPhone` in `viewport.js`). **Tablet = hybrid** (owner's decision 2026-10-23): desktop layout/HUD/flag/proportions, but the touch UI pieces of the phone — button bar, label above the button, queue 1-2-3, char-select strip, centred locks — are scoped `.touch` / `isTouch` (every touch device); only the phone layout and the enlargements for the small screen stay `.phone`: a lower virtual screen (`PHONE_DESIGN_H`) + pure CSS in **`public/styles-mobile.css`** (all touch + phone CSS, loaded after `styles.css`; one rule per selector, phone rules scoped to their screen — `.phone .lobby .opt`, never a bare `.phone .opt`) (full-width button bar, compact HUD columns, two-column char-select and lobby, one-row login); the phone char-select is **one cyclic swipeable strip** of all characters (`public/client/char-strip.js`, `strip-mode`; no arrows, the corner rune opens and closes the Hidden page) — check with `node tools/screens.mjs --only phone` (18 screens per device incl. lobby, colour roll, Hidden page, final round, game over; `--styles <f>` / `--compare <f>` = computed-style snapshot for CSS refactors, must be 0 diffs).

**Performance — "lite" graphics** (`public/client/perf.js`, plan + measured results in `docs/PERF_PLAN.md`): `html.perf-lite` / `perf.lite` is on by default on touch devices (auto; desktop switches itself on after ~3 s under 40 FPS; menu ☰ → GRAPHICS toggles LITE ↔ FULL (the first click leaves auto), or `?perf=lite|full|auto`). Lite = static 2-layer glow instead of 7 pulsing `drop-shadow`s, fewer aura streaks without `box-shadow`, no blur on the demon/Last Hope entrance and fog, opacity pulses instead of infinite `box-shadow`/`filter` animations (the "Úsporná grafika" section at the end of `styles.css`), and the `raf` draw loop capped at 30 FPS. Rules for new client code: an infinite animation must animate only `opacity`/`transform` (or get a static `.perf-lite` variant); never read layout (`getComputedStyle`, `offsetLeft`…) in the `raf` loop — use `liveActorPos()` (`placement.js`) for a moving figure; write per-frame styles via `setStyle()` (`style-cache.js`, writes only on change); draw into a canvas only while it is visible. Verify with `node tools/perf-probe.mjs --ab <commit>`.


### Telemetry (match data)

**Read `docs/TELEMETRY.md`.** With `TELEMETRY_DIR` set (on the VM `/home/arena/arena-data`, `deploy/arena.service`) the server writes every match to daily JSONL files: the **inputs** (`match_start` with the per-match `seed` + config, `team`/`pick`/`lock`/`ts`/`auto`/`next`) and **facts** (`round` segments per action read from the unredacted timeline via the non-enumerable `frame.act` tag, `game_end`, `match_end`). Owner's decisions (2026-10-29): only collection + download, no interpretations; **no player identity** (no names, no persons A/B) — sides are only `white` (p1) / `black` (p2). `telemetry/recorder.js` wraps the engine (`createRecordedEngine` = same API + `abort(reason)`; server.js uses it instead of `createEngine`); the engine itself is untouched. The server now seeds **every** match (`ARENA_SEED` or `crypto.randomInt`), so `telemetry/replay.js` / `node tools/replay.mjs <file|dir>` replays any match from the log on the commit it was played on; `test/telemetry.mjs` (in `npm test`) plays 40 bot matches of every format and requires the replay to reproduce the log exactly. Download: ☰ → ADMIN → DOWNLOAD DATA (one-time token via `admin_data_token`) or `GET /admin/data?key=<ADMIN_KEY>[&from=YYYY-MM-DD]` (gzip). Keep it replayable: no `Math.random`, no timer that changes state outside a recorded input; a new engine command must be wrapped in the recorder and replayed in `replay.js`.

### Sound & music

Client-only (engine/server unaware; golden unaffected). **Read `docs/SOUNDS.md` before touching sound.** Sounds are made in **`/sound-lab.html`** as a **sound pack** (zip) that anyone can build/download; **only the server owner installs one** (`tools/sound-pack.mjs install <zip> --activate` → `public/sounds/packs/<id>/<ver>/` + generated `packs/index.js`, committed + deployed; no upload endpoint). **Packs never change or propose game timing** — sounds adapt to the game. Pieces: `public/sounds/manifest.js` = base registry (event key → files `lib/<pack>/…`, `vol`, `fit`, **`status`: `default` = Claude's unheard guess / `picked` = owner's choice — never change a `picked` entry unasked**; `SOUND_SOURCES` licences; `SOUND_API_VERSION` + `KEY_MIGRATIONS`). Pure modules (Node + browser): `public/sounds/events.js` (timeline effect → key via `DIRECT`, `ONCE_PER_RUN`, move/dash from position deltas, each event's **window** = frame `delayMs`/run sum), `fit.js` (keep/fade/fit ±15 % to the window), `pack.js` (pack.json validate/migrate/compatReport — three version axes: `format`, `soundApi`, per-entry `madeForMs` vs `windows.json`), `zip.js`, `trim.js` (per-file `trim: {file: [startMs, endMs]}` = play only the main part; music loops inside it with a ≤1.5 s end→start crossfade via `playMusicLoop`; the lab auto-detects it on add). `public/sounds/windows.json` = windows measured from seeded headless bot matches (`npm run sounds:windows`; `--check` in `npm test` — regenerate after any timing/mapping change). `public/client/sound.js` plays layers base → active pack → lab draft (IndexedDB via `draft-store.js`, only with the lab's "try in game" flag); `sound-map.js` wires timeline + phase → music; `sound-ui.js` = the sound window (opened from the ☰ menu; mute + master/music/sfx sliders with −/+ steps, real device size on touch; key **M** = mute) + click sounds. Per-character keys `<event>.<char>` beat `<event>` (`hit.<char>` = the struck character). Renaming/removing an event key = bump `SOUND_API_VERSION` + `KEY_MIGRATIONS` + `node test/sound-pack.mjs --snapshot` (test fails otherwise). Tests: `test/sounds.mjs`, `sound-events.mjs`, `sound-fit.mjs`, `sound-trim.mjs`, `sound-pack.mjs`, `tools/sound-pack.mjs check` (all in `npm test`); `node tools/sound-smoke.mjs` = real-browser check (manual). Never play a sound derived from state the player can't see (labyrinth/trap redaction already filters effects).

### Admin & menu

**Admin = a player who logged in with the admin password (`ADMIN_KEY`) instead of a player password** (owner's decision 2026-10-21; the old open `?admin=1` mode is gone). The admin password also works as an entry password, so the admin plays normally. The server marks the socket (`socket.data.isAdmin`, recomputed from the handshake on every connection) and emits `session: { admin }` right after connecting; the client keeps it in `public/client/admin-state.js` (`html.admin` class). The socket events `admin_reset_room` (this room) / `admin_reset_all` (all rooms) work only for an admin socket; a reset sends `force_reload` to everyone in the room (players + spectators; reset-all also to the room browser) → the client reloads the page (fresh client version, lands in the room browser) and the server disconnects the socket 300 ms later; `GET /admin/reset-all?key=<ADMIN_KEY>` stays for scripts. Admin UI: the ADMIN section of the ☰ menu (everywhere; the old corner "Reset this room" button is gone — owner's decision 2026-10-29) and **RESET ROOMS** in the room browser. Without `ADMIN_KEY` nobody is admin.

**Spectators** (`public/client/spectators.js`): the server emits `spectators: { count, seatFree }` to the whole room on every change (spectate / leave / disconnect / seat, and once more after a disconnected player's reclaim grace runs out). Players and spectators see an **eye with the count** right of the ☰ button (above it on a phone; hidden at 0). A spectator gets the bottom bar **SPECTATING · TAKE SEAT · LEAVE** — LEAVE = `leave_room` (back to the room browser), TAKE SEAT (shown only when `seatFree`) = `take_seat` → `takeSeat()` seats them by the same rules as `join` (B first, then A) and they become a player (`you_are` ends spectator mode). `spectator` carries `{ roomId }`; the client keeps it in `sessionStorage` (`arenaSpectate`, `net.js`) and on the next `rooms` (RELOAD GAME, dropped connection) automatically spectates the same room again; LEAVE / take seat / admin reload forget it.

**Menu ☰** (`public/client/menu.js`, bottom-left, above every screen incl. stuck overlays): RELOAD GAME (`location.reload()` — the server reclaims the seat via `arenaId`, the login sits in `sessionStorage`; the escape hatch when the game gets stuck, essential in the installed app which has no browser refresh), full screen (where supported), SOUND (window from `sound-ui.js`) and the admin section. On touch the menu and windows render at real device size (`--ui-k` from `viewport.js`).
